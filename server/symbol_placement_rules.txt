Only place pins on the left and right side of the symbol. Do not combine or overlap pins. In order of most important to least: place PAD and GND pins in the bottom right corner, with PAD always the first/lowest pin from the bottom; place power supply pins starting from the bottom-left corner and fill upward from the bottom on the left side; place no connect pins in the bottom right above PAD/GND if present; place inputs on the left and outputs on the right except for crystal oscillator pins. Try to group other pins together by similar functionality (for example, SPI, I2C, RGMII, USB upstream, USB downstream, etc.).
Always separate groups by 100mil gaps unless there is extra spacing, then space out groups equal distance from each other.
Left side and Bottom denote lower values of x & y. Before generating the symbol provide an explanation for why you chose each pins position.
The Y coordinate of the top-left pin must always be -2.5mm. Build the left-side groups downward from that top-left anchor on the 2.5mm grid.
Place all crystal oscillator pins on the right side. Keep 10mm Y spacing inside the crystal oscillator group, and place the oscillator output pin above the oscillator input pin.
For exposed pads, thermal pads, or center pads, use fixed pin name PAD, pin number equal to the package pin count plus 1, and electrical type eElectricPower; do not default the exposed pad to pin 0 or name it GND.
Do not add the part number, comment, LibReference, or manufacturer part name as graphical text inside or around the symbol body. Set the part number only as the component Comment and/or parameters. Copy reference labels only as style references, not as text content; only explicit functional labels such as "USB Hub" may be drawn.
Set the component Comment equal to the Design Item ID / LibReference. Set the PartNumber property to exactly =Comment.
Set every schematic pin Description from the part datasheet. Do not keep pin descriptions copied from the reference symbol style pins.
Snap all generated symbol coordinates and primitive dimensions to a 2.5mm schematic grid, including pins, body rectangles, divider lines, labels, and designator placement.
When passing pin coordinates to create_schematic_symbol, use exact 2.5mm-grid mil values. One grid step is 98.425 mil; a 5.0mm row spacing is 196.85 mil. Do not use rounded 200 mil row steps, because they snap unevenly and create periodic 7.5mm gaps.
Use the currently open/reference component as the style source for pin length and all font settings. Generated pins, labels, delimiters, body primitives, designator, and parameters must keep the reference symbol's text size, font, line width, colours, and pin length; do not use Altium default styling when a reference component is available.
For connector symbols, default to no generated vertical separator/divider lines. Only keep vertical lines when they already exist in the reference symbol or the user explicitly asks to add them.
For connector mechanical mounting pins with pin numbers or pin names starting with MP, hide the pin designator/pin number while leaving the pin name visible.
For connector symbols, use designator XP? for headers and XS? for receptacles.
Connector descriptions must use comma-separated clauses like "16 Position Header, 0.4mm Contact Pitch, Stacking Height 0.8mm". Use "Mezzanine" instead of "Mezzanine Connector". Do not include the manufacturer or part number in the description.
For grouped symbols with left/center/right sections, keep the left and right side section widths equal but compact. Size both side sections from the widest pin-name label, measured from the pin anchor to the inside edge of the copied reference pin primitive, plus one 2.5mm grid step of clearance, rounded to the 2.5mm grid. Fallback character estimates must be conservative enough that long pin names do not touch or cross vertical divider lines. Do not preserve an overly wide reference side-section width; use the reference only for style, or as a fallback when pin-name width cannot be estimated. Only use SideSectionWidthMM when an explicit manual override is needed.
Draw horizontal delimiter lines only between functional pin groups, following the reference symbol style. Never place a delimiter inside a group, on the same Y coordinate as a pin row, or through pin-name text. Place each delimiter on the 2.5mm grid, normally halfway in the empty space between adjacent groups. Use short side-section delimiters on the left and/or right pin-name sections so the center functional label area stays clean unless the reference explicitly uses a full-width delimiter.
Preserve the reference component's rectangle and divider-line proportions except for the side-section widening needed to clear pin-name labels. Do not add gaps in vertical divider lines unless the user explicitly asks for that geometry.
Keep body borders and delimiter lines snapped to the 2.5mm grid and aligned like the reference symbol. For CH334P-style symbols, the body top/bottom should be one 2.5mm grid step outside the top/bottom pin extents.
For symbols with a functional center label such as "USB Hub", place the label at the top center of the full body rectangle by default. Its Y coordinate must sit one 2.5mm grid step below the top pin row/body top reference used by the generated symbol; for CH334P-style symbols this is Y=-5mm. The label X origin may be off-grid only when needed to visually center the label. If a center label contains several words, split it into two lines at the word break nearest the middle of the text and center-align both lines independently.
