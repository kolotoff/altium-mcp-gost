# Create Board Test Description

When the test deliverable includes connector-pin exports, firmware port
mapping, or supply-source/voltage fields, also follow
`skills/create-board-port-map/SKILL.md`; keep PCB pad nets distinct from traced
source nets in the test inventory.

Create a test-access document from the **currently open PCB**, without editing or saving the Altium design. Follow the repository `AGENTS.md` rules. This is a focused companion to `skills/create-board-description/SKILL.md`; its end-user mode is a useful reference for 3D/SVG export and net tracing, but a test description has different selection and layout rules.

## Inventory

Use `mcp__altium` readback from the active PCB. Select the union of:

1. Every component whose footprint name contains `TESTPOINT` (including net-named designators).
2. Every `SB*` designator. Identify actual solder bridges from the footprint; describe a switch or other control honestly rather than treating every `SB*` item as a solder bridge.
3. Every component with footprint `Keystone 5016`.
4. Every component pad with a real drilled hole of at least **1.00 mm**, a nonempty assigned PCB net, and a pad name that does not start with `MP` (case-insensitive). Select the component once, but list every qualifying pad. Do not infer hole diameter from the copper-pad dimensions or the assembly SVG's standalone mounting-hole circles.

The `get_component_pins` readback includes `hole_size` in **mils**; multiply by `0.0254` for millimetres. If a deployed server does not expose `hole_size`, add or restore that read-only field and re-query before asserting the hole set. `scripts/prepare_test_inventory.py` validates and deduplicates the readback; see [references/test-description-data.md](references/test-description-data.md) before preparing its input.

For each listed pad, retain the local PCB net and trace to a meaningful source net or source IC signal where the local name is generated or separated by a resistor, filter, selector, or bridge. Verify the connectivity before substituting names. The inventory helper refuses unresolved `Net*` source names; provide reviewed source-net overrides. An IC pin-function inference from a manufacturer pinout must be identified as such when the schematic net name is unavailable. Do not silently relabel an uncertain net.

## Images and document

- Export top and bottom orthographic PCB 3D PNGs with `export_pcb_3d_images(workspace_color="#FFFFFF", solder_mask_color="#0B3D2B")`, unless the user specifies another mask color. Retain the returned `pcb-3d-registration.json`. Export top and mirrored bottom assembly SVGs with `export_pcb_assembly_images(keep_svg=True)`. These Altium exports are read-only and must not save the PCB.
- Verify that several exposed workspace pixels, including all four corners, are exactly white. A white Altium workspace setting alone is insufficient when an older exporter uses the opaque renderer: it produces a shaded pink/gray gradient. The current exporter renders a transparent workspace onto a flat white canvas. If a legacy export still has the gradient, use `tools/normalize_pcb_3d_background.py` for the current deliverable and report that the Altium extension must be reloaded before future exports use the fixed renderer.
- Build a labeled top and bottom test map from those assembly SVGs using `tools/generate_board_test_maps.py`. Keep the original board outline and component geometry. Preserve mounting-hole circles only when their full circle lies inside the PCB outline; exclude out-of-board panel-rail holes on both sides. Hide the general copper `Pads` group. Scale the board to fill the map page within margins without changing its aspect ratio. Use actual PCB designators, never synthetic names, for test-point labels and legend entries. Distribute labels around and within the board near their targets; every callout needs a plain leader line ending at a circled anchor, with no triangular arrowhead. Reject intersecting labels, leaders, or anchor circles, and check the rendered maps visually. For each selected component with qualifying drilled signal pads, add a distinct source-net label anchored to every qualifying pad. Include a designator/source-net legend on each side, and reject missing or duplicated designators or pad callouts.
- For each side, use `tools/generate_board_test_3d_maps.py --registration ...` to place the same labels and nonintersecting leader routes on its orthographic 3D export. The 3D camera includes protruding component bodies and is therefore wider than the assembly-SVG board view; never compensate with `xMin`/`xMax` alignment or a side-specific pixel offset. Map the camera's physical millimetre bounds into the SVG viewport, including the bottom-side mirror. The 3D overlay has no drawn circles: extend each leader to its target and retain the board image aspect ratio. Place this annotated 3D image immediately after the matching assembly-SVG map in the DOCX.
- Generate the **same-sized local 3D crop style** for every selected test point and component with `tools/crop_native_pcb_3d_export.py --top-svg ... --bottom-svg ... --registration ...`. The crop center and the locator arrow must use the same camera registration as the full-board overlay; mapping SVG coordinates directly across the entire PNG shifts every arrow when components expand the 3D camera. The crop must come from the correct side, center the selected item, and show its designator and locator. Visually inspect a contact sheet and fix only genuine orientation exceptions, not global coordinate offsets.
- Create a task-local JSON specification following [references/test-description-data.md](references/test-description-data.md), then run `tools/generate_board_test_description_docx.py`. Start with the two full-board 3D views, followed by each side's labeled SVG map and matching annotated 3D image. Fit every SVG to its DOCX page using its viewBox aspect ratio, never independent width/height stretching. Give each selected item a local crop and a pad table with pad number, PCB net, source net, and hole diameter when applicable. For solder bridges, state default open/closed state and the exact effect of changing it. Include a concise selection-rule/count summary.
- Use the `documents` skill's render-and-inspect workflow. On Windows, if its bundled renderer cannot find LibreOffice, export a temporary PDF through installed Word and rasterize every page with the bundled Poppler tools. Inspect every page for clipping, orphaned tables, unreadable maps, and blank pages. Check unique-item and per-category counts against the Altium inventory, and search extracted text for unresolved generated net names. Deliver the DOCX only after visual and content QA.
- After any map revision, regenerate the assembly and annotated-3D SVGs and their same-named PNG fallbacks, then rebuild the final DOCX. Inspect its embedded SVG and PNG media to confirm they are the current files. Verify the retained `StandaloneMountingPads` circles against `BoardOutline` in the assembly SVGs; a page render can clip an invalid out-of-board circle and conceal stale geometry.
- Reject a missing or size-mismatched 3D registration instead of falling back to aspect-only placement. Confirm each annotated 3D SVG image has `data-registration="altium-camera-mm"`, and spot-check one target near each horizontal edge on both sides.

### Board-independent registration

Treat `pcb-3d-registration.json` as part of the paired top/bottom export, not as board-specific tuning. It records each camera's physical bounds, pixel dimensions, and horizontal mirror state. Recreate it whenever the board, camera framing, side, DPI, or render dimensions change; never reuse it for another board or edit its bounds to make labels look closer. The assembly SVG supplies physical component and pad coordinates, while the registration is the only conversion from those coordinates to 3D pixels. This same conversion must drive annotated-map placement, local crop centers, and locator arrows. A protruding component can expand any camera edge on any board, so fixed left/right padding, aspect-only scaling, and designator-specific offsets are invalid.

### Language modes

The default `source` mode preserves the task's source wording. Use `ru` for an explicitly Russian document, `en` for English, `zh` for Simplified Chinese, or `en-zh` for a combined English and Simplified Chinese document. Apply the selected mode consistently to `generate_board_test_maps.py`, `generate_board_test_3d_maps.py`, `crop_native_pcb_3d_export.py`, and `generate_board_test_description_docx.py`. Supply translated modes with `--translations <catalog.json>` when reader-facing source prose needs translation; read the catalog schema in [references/test-description-data.md](references/test-description-data.md). The catalog translates reader-facing prose only. Do not translate designators, footprint names, pad numbers, PCB nets, source nets, dimensions, file paths, or the board name. Copy `board_name` verbatim from the Altium document name or approved project identifier, including every dot, underscore, hyphen, space, revision marker, and other symbol; do not prettify or normalize it for titles. The DOCX generator rejects a title or subtitle that omits or changes the exact `board_name`. Reject missing requested-language values for localized objects, search the finished DOCX for untranslated source-language prose, and visually verify an appropriate font in headings, tables, map legends, and crop labels.

Do not save the open PCB. Report if Altium's saved/dirty state is ambiguous or changes unexpectedly.
